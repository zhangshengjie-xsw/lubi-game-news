# 露比游戏新闻台 v0.1.3

本版本修复 RSS XML 解析防护，用于露比插件市场正式审核与安装联调。

## v0.1.3 更新内容

- 新增 news.include_summary，默认 true，控制是否向回复模型和来源展示提供 RSS 摘要。关闭后仅提供标题、日期、来源及链接。
- 调用详情增加“插件版本”和“包含摘要”，便于确认更新生效。
- 保留 count、max_age_hours、cache_minutes 的名称及默认值，供验证升级后用户配置保留。

## v0.1.2 更新内容

- 为重新申请市场审核发布新版本，功能代码与 v0.1.1 相同。
- 保留 RSS XML 安全解析修复，不覆盖历史版本标签。

## v0.1.1 更新内容

- 组件类型由市场从源码自动识别，manifest 不再重复声明 `comp_types`。
- 在 XML 解析器层拒绝 DTD 和自定义实体，修复不同 XML 编码可能绕过字节检查的问题。
- 配置继续使用插件根目录的 `config.toml`，字段及默认值保持不变。

GitHub 已批准的 v0.1.0 保持原样；本次将使用新版本发布，不覆盖旧标签。

按露比 plugin_template 编写的 Hook Command 插件，不提供斜杠聊天指令，不直接调用模型或发送消息。

## 请求播报

对露比说“播报一下游戏新闻”或“最近有什么游戏资讯”。该消息被宿主选为回复对象后，
`BEFORE_REPLY_CONTEXT` 调用 `news` Command，读取 indienova 的公开 RSS，最多取三条，
将标题、发布时间、原文地址和短摘要交给宿主回复模型，用露比本身的语气讲述。
普通聊天不发起联网请求。插件不会强制 Planner 回复每条消息，不保证逐条口播，不提供追问原文检索。

## 宿主要求

需要支持 `BEFORE_REPLY_CONTEXT` 的露比宿主，本项目随配套宿主改动一起测试。
不能装到原版 MaiBot；未发布最低版本号，但新 Hook 是否存在仍由加载器检查。
接入的是 DefaultReplyer 群聊/弹幕回复路径，不包含独立的 PFC 私聊回复器。
该 Hook 最多绑定一个组件，不占用内置联网搜索节点。

## 配置

插件声明 config.toml，宿主生成配置并提供网页编辑：

```toml
[news]
count = 3
max_age_hours = 48
cache_minutes = 15
include_summary = true
```

count 为 1—3，max_age_hours 为 1—168，cache_minutes 为 1—60。默认取最近 48 小时资讯，
不足三条时按实际数量播报，不拿旧新闻凑数。缓存 15 分钟，读取缓存仍按当前时间过滤。
媒体包含游戏资讯、评测和开发文章，首版不声称每条都是突发新闻，也不按热度排名。
来源：https://indienova.com/feed/ 。不抓取文章全文，不需要 API 密钥。

## 网页查看来源

打开插件详情 → 游戏新闻台组件 → 对应调用详情 → 新闻来源，查看标题、发布时间、
来源、原文链接和摘要。通过框架原生 add_fields 和表格声明展示，不额外建立网页。
链接是否可点击取决于宿主通用字段渲染；始终提供完整 HTTPS 地址。

## 失败及停用

超时、RSS 无效、来源不可达时给宿主明确的资料获取失败说明，不以旧缓存冒充新结果。
没有近期资讯时说明没有资料。停用插件/组件后沿用框架默认行为，不再补充新闻资料。
缓存只在内存中，停用、重载和升级后重新获取；首版不保存播报历史、不做跨请求去重。

## 本地验证与发布

通过露比插件市场安装后启用。宿主端配套测试位于其 tests/plugin_system/test_game_news.py，
覆盖正式 Hook 派发、三种回复模式的 Prompt 接入、缓存、失败降级、来源展示数据和取消释放。
插件本体需随支持新 Hook 的宿主一同使用，单独安装到旧宿主不能生效。
发布仓库根目录包含 plugin.py、commands.py、news.py、_manifest.json、README.md 和 LICENSE。
Python 依赖在 manifest.python_dependencies 声明，由露比复用或安装 aiohttp。
